# PHASE 07 CHECKLIST

## Quality planning
- [ ] `docs/quality-plan.md` exists
- [ ] It was written before construction began (check the date)
- [ ] Quality objectives are stated as numbers, not aspirations
- [ ] Standards to be followed are named (IEEE, ISO/IEC, organisational)
- [ ] Tools and techniques for quality are selected and listed
- [ ] Procedures for maintaining quality are defined

## Reviews
- [ ] Requirements were reviewed before design started
- [ ] Design was reviewed before construction started
- [ ] Code was reviewed before merge
- [ ] Each review record names its type: peer review, walkthrough, or inspection
- [ ] Inspections (where used) name Moderator, Reader and Recorder
- [ ] Review findings were dispositioned, not just recorded
- [ ] Review type matches artifact risk

## Audits
- [ ] A process compliance audit was performed
- [ ] The auditor is independent of the delivery team (RIGOUR 3+)
- [ ] Documentation completeness was checked
- [ ] Standards adherence was checked
- [ ] Findings have owners and dates

## Metrics
- [ ] At least one product metric recorded
- [ ] At least one process metric recorded
- [ ] At least one project metric recorded
- [ ] Metrics are in `.ilana/metrics.csv` with a source for each value
- [ ] Defect root causes categorised by phase
- [ ] No superlative claim in any report lacks a supporting number

## Quality attributes
- [ ] Correctness assessed with evidence
- [ ] Reliability assessed with evidence
- [ ] Efficiency assessed with evidence
- [ ] Usability assessed with evidence
- [ ] Maintainability assessed with evidence
- [ ] Portability assessed with evidence
- [ ] Security assessed with evidence
- [ ] Anything unmeasured is marked UNVERIFIED, not "good"
