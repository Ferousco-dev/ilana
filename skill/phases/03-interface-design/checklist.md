# PHASE 03 CHECKLIST

## Type and structure
- [ ] Interface type chosen and justified: text-based, graphical, or both
- [ ] If both, the two agree on vocabulary and on operation semantics
- [ ] Layout model is consistent across screens or commands
- [ ] Related controls grouped, unrelated controls separated
- [ ] Naming is consistent: the same action has the same name everywhere

## Simplicity
- [ ] The primary task is completable without documentation
- [ ] Time-to-first-success measured or estimated
- [ ] Every shortcut relates visibly to a longer procedure
- [ ] Nothing is on screen that this task does not need

## Visibility
- [ ] Every option required for the current task is visible
- [ ] Nothing redundant competes for attention
- [ ] System state is discoverable without a log

## Feedback
- [ ] Every action produces an observable response
- [ ] Every operation over one second shows progress
- [ ] Every error message names the cause and the next step
- [ ] Messages use the user's vocabulary, not the implementation's

## Tolerance
- [ ] Every destructive action has undo, confirmation, or both
- [ ] Input formats are tolerant where tolerance is unambiguous
- [ ] The user's work survives an error
- [ ] Unreasonable input is rejected clearly; reasonable variation is accepted

## Accessibility (RIGOUR 3+)
- [ ] Colour is not the only carrier of meaning
- [ ] Contrast checked
- [ ] Keyboard reachable and operable throughout
- [ ] Accessible names present
- [ ] Focus visible and ordered
- [ ] Reduced-motion respected

## Traceability
- [ ] Every user-facing REQ maps to at least one UI element
- [ ] Every UI element traces back to a requirement
