# PHASE 09 QUESTIONS

Maximum five.

1. Who is the audience for this model or document: business stakeholders, developers, testers,
   auditors, or end users? The answer determines the notation and the register.
2. Is this modelling the process as it **is**, or as it **should be**? Both are legitimate;
   confusing them is not.
3. Where does work currently get stuck or handed back? Those are the decision points and
   bottlenecks the model must show.
4. What documentation already exists, and is any of it out of date? (Out-of-date documentation is
   worse than none, because it is trusted.)
5. Could someone who joined yesterday build and run this system from what is written down?

## Ask when choosing a notation

6. Does this process cross organisational roles and systems? (If yes, BPMN with swimlanes. If it
   is inside one program's control flow, an activity diagram.)
7. Will this model be executed by a workflow engine, or only read by humans?
