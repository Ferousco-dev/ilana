## Multiple choice

**Q1.** A team gathers requirements for a banking application and communication with stakeholders
is poor. The most likely direct consequence is:
A. product metrics automatically switch to process metrics
B. incorrect or incomplete requirements, which may affect the entire project
C. the CMMI level advances due to flexibility
D. ISO/IEC 12207 classifies the project as an organizational process
*Answer: B*

**Q2.** A Business Analyst approves ambiguous requirements without stakeholder validation, and
during implementation multiple developers interpret them differently. The engineering weakness
most directly responsible is:
A. poor requirements engineering and ineffective communication
B. database optimisation
C. software refactoring
D. configuration management
*Answer: A*

**Q3.** "The system must operate 24/7" is which type of requirement?
A. functional  B. non-functional  C. domain  D. constraint
*Answer: B*

**Q4.** "Payment handling must satisfy PCI-DSS" is which type of requirement?
A. functional  B. non-functional  C. domain  D. interface
*Answer: C*

**Q5.** Which activity BEST supports ethical software development during requirements engineering?
A. concealing project risks from clients
B. clearly documenting system limitations and assumptions
C. reducing stakeholder participation
D. eliminating requirement validation
*Answer: B*

## Scenario

**S1.** A stakeholder tells you: "the system should be user-friendly and fast, and it needs to
handle a lot of users." Rewrite this as three properly formed requirements. State what you would
have to ask to write them, and why the original sentence cannot be tested.

**S2.** You are three weeks into construction. The client asks for a feature that would change the
data model. Describe exactly what happens next, naming the artifacts produced and the decision
points, and say who decides.

**S3.** You are building a hospital appointment system. Nobody on the project has mentioned any
regulation. Describe how you would establish the domain requirements, and what you would record if
it turns out none applies.

**S4.** Two stakeholders want incompatible things: the head of reporting wants richer analytics,
and operations wants sub-second response times, and both compete for the same resources. Describe
your procedure. State explicitly what you would NOT do.

## Marking notes

- S1 must produce a number and a unit for each. A rewrite that keeps "fast" fails.
- S2 must have impact analysis **before** approval. Any answer that implements first fails.
- S3 must include recording the negative result. "No regulation applies" without saying which were
  checked is the failure being tested for.
- S4 must not resolve the conflict unilaterally. Facilitate, escalate, record.
