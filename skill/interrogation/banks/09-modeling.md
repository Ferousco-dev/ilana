## Multiple choice

**Q1.** Which notation is better suited to modelling a business process crossing several
organisational roles, with extensive swimlane support?
A. UML activity diagram  B. BPMN  C. data flow diagram  D. entity relationship diagram
*Answer: B*

**Q2.** In an activity diagram, which element splits a single activity flow into two concurrent
activities?
A. merge node  B. fork node  C. decision node  D. join node
*Answer: B*

**Q3.** Which IEEE standard covers the Software Design Description?
A. IEEE 830  B. IEEE 1016  C. IEEE 829  D. ISO/IEC 25010
*Answer: B*

**Q4.** Which IEEE standard covers Software Testing Documentation?
A. IEEE 830  B. IEEE 1016  C. IEEE 829  D. ISO/IEC 12207
*Answer: C*

**Q5.** A stated limitation of UML activity diagrams is that they:
A. cannot show decisions  B. can become complex for large systems and are less suitable for
highly dynamic business processes  C. have no standardised notation  D. cannot show sequence
*Answer: B*

**Q6.** Why does documentation remain important even in Agile environments?
A. Agile prohibits documentation
B. Agile values working software but still requires sufficient documentation to support
   communication, maintenance, compliance and knowledge transfer
C. documentation is needed only after software retirement
D. documentation replaces stakeholder collaboration
*Answer: B*

## Scenario

**S1.** Your process diagram shows the approval workflow as everyone believes it should work. In
practice there is an informal step where the team lead checks the change before it reaches the
approver. Should the diagram include it? Justify from the characteristics of a good process model.

**S2.** A new engineer joins and cannot get the system running from the documentation. Frame this as
a measurement rather than a complaint, and say what you would do with it.

**S3.** You are asked to model the course registration process. Produce the six standard sections
for it.

## Marking notes

- S1 must include the informal step, citing accuracy: a model must represent actual operations.
- S2 must treat each point where the newcomer got stuck as a documentation defect and record it.
- S3: purpose (register students), inputs (student details, course catalog), activities (login,
  course selection, validation, approval), outputs (registration slip), plus scope and roles.
