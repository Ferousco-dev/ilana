## Multiple choice

**Q1.** A software engineer is pressured by a project manager to skip the scheduled integration
testing phase to deliver a medical portal on its original deadline. This action is:
A. acceptable, as long as product metrics indicate a high LOC volume
B. unethical, because neglecting quality or bypassing established process activities for speed or
   cost is an ethical violation
C. encouraged under CMMI Level 1 to foster individual developer heroics
D. a recognised task optimisation technique
*Answer: B*

**Q2.** According to the ACM/IEEE code, which clause is directly violated if an engineering team
knowingly releases a faulty, unsafe software system into a public healthcare environment?
A. infrastructure management  B. process cycle time standardisation
C. public interest and product quality  D. localised project scheduling adherence
*Answer: C*

**Q3.** A development team experiences a major failure because the system architecture was designed
without consulting the database engineers, resulting in massive data type mismatches across
structural components. Which phase suffered from a failure in team dynamics and collaboration?
A. requirements gathering  B. design decisions  C. system deployment  D. process assessment
*Answer: B*

**Q4.** A developer uses an open-source library strictly protected by copyright without obtaining a
proper licence or giving credit, claiming it was necessary to speed up development. This
represents a failure to respect:
A. intellectual property rights  B. process cycle time
C. process standardisation  D. usability attributes
*Answer: A*

**Q5.** According to the ACM/IEEE code, if a software engineer accepts a complex cryptography
architecture project despite lacking the necessary skills, training or technical capability, they
violate the principle of:
A. client and employer confidentiality  B. professional competence
C. product defect density  D. schedule adherence
*Answer: B*

**Q6.** In software engineering, "team dynamics" is formally defined as:
A. the absolute number of lines of code written by a project manager per week
B. the patterns of interaction, communication and collaboration among team members
C. the statistical variance between planned and actual costs
D. the configuration management tools utilised during software maintenance
*Answer: B*

**Q7.** A software project repeatedly experiences misunderstandings, duplicated implementation,
delayed testing and deployment failures. Which underlying problem best explains all these symptoms?
A. poor team dynamics  B. excessive documentation
C. database redundancy  D. high processor utilisation
*Answer: A*

**Q8.** A software project experiences duplicated implementation because two developers unknowingly
implement the same module independently. Which team characteristic was most likely absent?
A. clear roles and responsibilities  B. fault tolerance
C. continuous deployment  D. high availability
*Answer: A*

**Q9.** A developer hesitates to report a critical software defect because team members frequently
assign blame. Which characteristic of an effective team is most lacking?
A. trust and respect  B. functional decomposition
C. database optimisation  D. software reusability
*Answer: A*

**Q10.** During a design review, two senior architects disagree about the most appropriate system
architecture. According to effective conflict management principles, they should FIRST:
A. ignore each other's opinions
B. evaluate both architectural alternatives objectively using agreed technical criteria
C. cancel the design review
D. allow project deadlines alone to determine the architecture
*Answer: B*

**Q11.** Which project would most likely require strict plan-driven governance despite using DevOps
automation?
A. personal blogging website  B. national electronic voting system
C. student portfolio application  D. online discussion forum
*Answer: B*

**Q12.** Which combination of Agile and plan-driven practices is most appropriate for developing
regulated financial software?
A. Agile development supported by formal documentation, compliance reviews and controlled change
   management
B. code-and-fix methodology  C. pure Kanban without documentation
D. informal prototyping only
*Answer: A*

## Scenario

**S1.** During final testing of a cloud-based electronic health record system, the QA team discovers
that under high concurrency, patient records may occasionally be retrieved incorrectly. The project
manager insists on deployment to meet contractual deadlines. The product owner argues the issue
affects less than 0.01% of transactions. State the correct action and the principle that governs it.

**S2.** A software engineer intentionally commits proprietary source code from a previous employer
into a new company's repository. Name the ethical issues violated and describe what should happen.

**S3.** Your team refuses code reviews because everyone is senior. Write the argument you would make
to change this, using the specific consequences rather than an appeal to policy.

**S4.** You are choosing a process style for a national health records platform that requires
continuous feature evolution while maintaining regulatory compliance. State your choice and justify
it against the specific project characteristics.

## Marking notes

- S1 must delay deployment, disclose the risk to stakeholders, resolve the defect, and repeat
  verification before release. Public interest and patient safety override schedule pressure. Any
  answer that ships with internal documentation only fails.
- S2 must name both confidentiality and intellectual property rights.
- S3 must argue from consequences: reviews identify errors, improve quality and reduce risk before
  release; experience changes what a review finds, it does not remove the need for one.
- S4 should choose hybrid: Agile development inside plan-driven governance, justified by the
  combination of evolving requirements and regulatory obligation.
